## 1. サイトは3つある（役割を混ぜない）＋LINE配信

| # | 用途 | 置き場所 | 見る人 | 状態 |
|---|---|---|---|---|
| 1 | **公開サイト**（フォロワー向け・広告） | `kajikeiba.com` | 誰でも | 稼働中 |
| 2 | **運営用**（予想を作って画像をXに貼る） | `seventh-well.com/odds/tweet.html` | 本人のみ | 稼働中（未保護） |
| 3 | **知人向け**（全部見せる） | `seventh-well.com/lab/` | 知人 | 稼働中 |
| 4 | **LINE配信**（発走5分前・買い目と配分） | LINE公式「カジ競馬」@469aivdf | 友だち登録者 | 2026-07-31 無人運転開始 |

### LINE配信（#4）の要点 — ★他の3つと予想が違う★

- **モデルが違う**: `narM`（34列・**人気popを特徴量に含む**）。オッズを見て採点する。
  ★narMを tweet.html / 公開サイトに載せてはいけない★（「予想は事前に出す」建前が壊れる）。
  実測: ◎複勝率 76.1%（≒市場と同等）。tweetの事前モデル(66.4%)とは別物。
- **朝に配信対象が決まる**: 9:20の無人運転が全レースを採点し、gap降順の上位3レースを固定。
  その時点で「📋 本日の配信予定」を配信する（＝加入者は事前にどのレースか分かる）。
- **配信は発走5分前**（T-3〜7分）。買い目は単勝・複勝・馬連・馬単まで（3連単は入れない）。
- **配分は床保証型**: ◎が3着内なら必ずプラスになるよう複勝に下限を置き、残りを上振れ側に配る。
- **見送りも配信する**（出走取消・オッズ条件を満たさない等 → ⚠つきで理由を送る）。
- **3レース終了後に総括**（各回収率＋トータル）。
- ★通数の制約★ LINEの「通数」は **配信回数 × 友だち数**。現行設計は月190回なので、
  **無料プラン（200通）では友だち1人＝自分専用でしか成立しない**。2人目から月5,000円。
  詳細と対策（応答メッセージは無料・無制限）は docs/BUSINESS.md 柱B'。
- 実体: `deploy/tweet.html` の LINE モジュール ＋ `php/line_push.php`（broadcast）。
  無人運転は `tools/line-runner/run_line_day.js`（headless Edge）をタスクスケジューラで毎朝9:20。
  ドライラン = `?dry=1`（送らず `line_outbox/*.dry.txt` に保存）。

**公開サイトに入れてよいのは「誰に見られてもいいもの」だけ。**
`backtest/deploy.py` の `PUBLIC_MAP` がその線引きで、tweet.html と lab は入れていない。

デプロイ:
```
python backtest/deploy.py --site public    # kajikeiba.com（既定）
python backtest/deploy.py --site legacy    # seventh-well.com/odds/
```

**原則:**
1. 数を先に決めて埋めない（20人格ありきにしない）。データで区別できる観点だけ作る。

3. 弱い人格も消さない。効かなかったことを消すと、残りの数字も信用できなくなる。

## 重賞データ /data/jusho/（2026-07-20）

中央の重賞143レースの過去データ（人気別・枠順別・脚質別の勝率/複勝率＋近年の勝ち馬）。
1ページのSPAで `?r=レース名` で切り替え（143個の静的HTMLにはしない。需要を見てから静的化）。

- 集計: `build_jusho_data.py`（生ダンプSEから枠・コーナー通過順を読む）→ `data.json`（195KB）
- ページ: `gen_jusho_pages.py`
- 重賞カレンダー(/calendar/)の各レース名から `?r=名前` でリンク。
- SINCE=2015（過去10年に絞る。傾向は最近が効く）。3回以上施行された重賞のみ。
- 脚質は各年の最初のコーナー通過順÷頭数（コースのペース傾向の目安）。

検算: 有馬記念1番人気 複勝55%(11回) / 皐月賞 複勝58%(12回) と実態に整合。
