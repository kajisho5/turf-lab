## 0. 最初に認めるべきこと

手元の実測はこうなっている。

| 事実 | 数字 | 出所 |
|---|---|---|
| 13人格すべてが市場に負けた | 最良61.9% vs 市場76.4% | `bt_personas.js` |
| 戦略43種の総当たりで100%超はゼロ | 天井92.2% | `ROI_SEARCH_2026-07-19.md` |
| モデルの◎は「1番人気を買う」に負ける | 78.5% vs 88.3% | `FACTS.md` |
| 券種を全部買うと大きく負ける | 単勝71.7% / 3連複47.7% | `jra_vs_nar.py` |

**つまり「当たる予想を売る」という商売は、こちらのデータでは支持されない。**
それでも売っている競争相手は、(a) 生存バイアスの見せ方をしているか、
(b) 検証していないか、のどちらか。

ここを曖昧にしたまま商品を作ると、遅かれ早かれ矛盾する。
**最初に商品の定義を変える必要がある。**

## 1. 競馬で人が金を払っているもの（何を売るのか）

| 買われているもの | 実在するか | こちらが提供できるか | 評価 |
|---|---|---|---|
| ① 当たる予想 | 継続的には**存在しない** | ✗ 検証で否定済み | **売らない** |
| ② 情報の整理・時短 | する | ○ すでに作った | 広告で回収 |
| ③ 負けを減らす判断 | する（自覚は薄い） | ◎ **データで裏が取れる** | **主力** |
| ④ 当たってる感・語れるネタ | する | ○ 人格別の印が効く | 集客 |
| ⑤ 帰属・コミュニティ | する | △ Xアカウント次第 | 中期 |

### ③が主力になる理由

こちらのデータが唯一はっきり支持しているのが「**買わない判断**」である。

| ゾーン（スコア差） | ◎の複勝率 | レース数 |
|---|---|---|
| 鉄板 | 77.3% | 4,782 |
| 勝負 | 72.0% | 19,074 |
| 狙い目 | 65.8% | 34,669 |
| 様子見 | 60.4% | 45,625 |
| **見送り** | **55.2%** | 68,422 |

差は22ポイント。**当てる力は無くても、「読めないレース」を判別する力はある。**
これは検証可能で、誇張の余地がなく、しかも競合が売りたがらない
（「買うな」と言う商品は売りにくいので、市場が空いている）。

言い換えると商品はこうなる。

> **勝たせる商品ではなく、「無駄玉を減らす」商品。**
> 回収率100%は超えない。それは最初に言い切る。

## 2. ポジション

```
netkeiba        情報量で勝負。総合デパート。勝てない。
SPAIA           AI予想18人格＋データ。有料会員。物量で勝てない。
予想サイト各社   「当たる」を売る。検証は出さない。ここには行かない。

カジ競馬        「検証を全部出す」ことだけで差別化する。
                効かなかったことを公開できるのは、データを持っている側の特権。
```

**唯一の堀（moat）: 自分の負けを公開できること。**
これは資本でも物量でも真似されない。真似した瞬間、相手の既存商品が矛盾するため。

すでに公開済みで、競合が絶対に書けない見出し:
- 「AI予想は市場に勝てるのか → 負けています」
- 「AI予想家13人の通信簿 → 市場を超えたのは0人」
- 「新馬戦9番人気の回収率26.6% → 何も言えていません」

## 3. 収益の3本柱と、必要な規模

### 柱A: 広告・アフィリエイト（無料ページ）

- **競馬系アフィリエイトは単価が高い**（口座開設・有料コンテンツ登録など）。
  ディスプレイ広告より、こちらが本命。
- ディスプレイのRPMは日本の競馬メディアで概ね数百円/1,000PV。
  **※この数値は業界の相場感であって実測ではない。最初の1か月で必ず実測に置き換える。**

必要PVの見当（RPM 300円と仮定した場合）:

| 月間PV | 広告収入の目安 |
|---|---|
| 1万 | 3千円 |
| 10万 | 3万円 |
| 100万 | 30万円 |

**結論: 広告だけで意味のある額にするには最低10万PV/月が要る。**
そこまでは「収益」ではなく「計測のための実験」と割り切る。

### 柱B: 有料（1日券・月額）

売るのは①ではなく③。具体的には:

- 今日の全レースの**見送り判定**（買うべきでないレースの明示）
- 券種の到達点（このレースは単複まで／ワイドまで／3連単まで）
- 資金配分の目安
- 人格の一致・不一致（13人格が割れているレース＝読めないレース）

価格帯の考え方: 1日券は「1レース分の馬券代」以下でないと心理的に通らない。
月額は「1日券×5回」程度に置くと日次から月次へ移行しやすい。
**具体額は無料ページのPVと滞在時間を見てから決める。先に決めない。**

### 柱C: X（@kaji_keiba）

売上ではなく**集客の心臓**。フォロワー10万はここの結果。
サイトはXの受け皿であって、逆ではない。

### 柱B'（2026-07-31 稼働開始）: LINE配信 — 柱Bの実物

柱Bで「売る」と書いたもの（見送り判定・券種の到達点・資金配分）を、
**先に無料のLINE配信として実装して回し始めた**。LINE公式「カジ競馬」@469aivdf。

- 毎朝9:20に無人で全レース採点 → 勝負レース3件を決めて**予告を配信**
- 各レースの発走5分前に**買い目＋資金配分**を配信（単複〜馬単。3連単は入れない）
- 見送りも理由付きで配信 / 3レース終了後に回収率の総括を配信
- 中身はオッズ込みモデル `narM`（tweetの事前予想とは別物・詳細は SITE_MAP.md §1）

**まず無料で運用実績（＝配信ログと実回収率）を貯める。** 課金の判断はその後。
理由: 柱Bの商品価値は「当たる」ではなく「毎日ちゃんと届いて、外した日も逃げない」
という運用の信頼で、それは実績でしか示せない。
### ★制約（2026-07-31 訂正）: LINEの「通数」は 配信回数 × 友だち数 ★

**当初「月114通で無料枠200通に収まる」と書いたのは誤り。** LINEの通数は
「メッセージを送った回数 × 送った友だちの数」でカウントされる（[公式](https://www.lycbiz.com/jp/service/line-official-account/plan/)）。
現行設計の配信回数は**月190回**（予告38＋買い目/見送り114＋総括38）。

| 友だち数 | 月間通数 | 必要プラン |
|---|---|---|
| 1人（自分だけ） | 190通 | 無料（200通）※ぎりぎり |
| **2人** | 380通 | **ライト ¥5,000/月** |
| 26人 | 4,940通 | ライト ¥5,000/月（上限） |
| 100人 | 19,000通 | スタンダード ¥15,000/月 |
| 157人 | 29,830通 | スタンダード ¥15,000/月（上限） |

**つまり現行設計は、無料プランでは友だち1人＝自分専用でしか成立しない。**
2人目が入った瞬間に月5,000円が発生する。100人で月15,000円。
配信そのものが原価になる構造なので、**友だちを増やす前に設計を決める必要がある。**

#### 抜け道: 応答メッセージ（Reply API）は通数にカウントされない・無制限

ユーザーの操作に対する返信は無料（[LINE Developers](https://developers.line.biz/ja/tips/2026/05/28/how-to-count-messages/)）。
→ **押し配りをやめて「引かせる」設計にすれば原価はゼロにできる。**

| 案 | 月間配信回数 | ライト¥5,000で | スタンダード¥15,000で |
|---|---|---|---|
| 現行（全部push） | 190回 | 26人 | 157人 |
| 予告＋総括だけpush・買い目はリッチメニューで引く | 76回 | 65人 | 394人 |
| **予告だけpush・あとは全部引かせる** | 38回 | 131人 | 789人 |

推奨は3案目。朝の予告で「17:40 園田6R」と時刻を知らせ、
本人がその時刻にリッチメニューを押すと**その場の買い目が返る**（無料・無制限）。
実装には Webhook 受け口（php）とリッチメニュー設定が要る。

## 4. 集客の設計 — いま最大の穴

### 穴: レースページがSEOで存在していない

```
現在  /race.html?id=202602011212     ← noindex・クエリ文字列・JSで後描画
```

問題が3つある。

1. `noindex` を付けている（そもそも検索対象外）
2. クエリ文字列のURLは評価されにくい
3. **中身をJSで後から入れているので、クローラが見るHTMLは空**

競馬メディアの検索流入は「**○○（レース名） 出馬表**」「**○○ 結果**」の
ロングテールで成り立っている。1日36〜80レース×365日＝**年間2万ページ**の
検索資産を、いま丸ごと捨てている。

### 対処

```
/race/202602011212/          ← .htaccess で書き換え、PHPで**サーバー側にも**出力
```

- URLをパス形式にする
- **最低限の内容（レース名・出走馬・結果・払戻）をサーバー側でHTMLに出す**
  （JSでの装飾はその上に乗せる）
- レースごとに `<title>` `description` を出し分ける
- 終わったレースは結果ページとして残す（過去分がそのまま資産になる）

サーバーはPHPが動く（`proxy.php` が稼働中）ので、実装できる。
**これが集客上いちばん効く一手。** 記事を10本書くより、この1つのほうが大きい。

### 記事の役割

記事はSEOの主力ではなく、**Xで拡散させる弾**。
「効かなかった検証」は1本1本がそのままスレッドになる。
毎週1本出せば、年52本の拡散ネタになる。

```
kajikeiba.com
│
├ /                          今日のレース一覧          【集客・回遊】
│   └ 中央⇄地方トグル、日付、場タブ

│   ├ 結果・払戻             サーバー側で出力（過去分が資産になる）

│
├ /ai/                       AI予想家の成績（通信簿）  【信用】
│   └ /ai/{id}/              人格ごとの詳細・外した例も出す
│
├ /data/                     検証記事                  【拡散】

│   └ （今後）見送り / 券種の壁 / 資金配分
```

**設計原則: 無料ページで信用を作り、有料ページで時間と判断を売る。**
無料側に広告、有料側は広告ゼロ（有料の見本になるため）。

## 7. やらないこと

| やらないこと | 理由 |
|---|---|
| 「当たる」「勝てる」と言う | 実測で支持されない。1回言うと全部の数字が疑われる |
| 勝ったレースだけ並べるページ | 生存バイアス。分母を誤魔化さない方針と矛盾 |
| 的中率・回収率の期間を都合よく切る | 同上 |
| 人格の水増し | 区別できる観点が増えたときだけ増やす |
| 推定値での穴埋め | 公開している成績が当てはまらない別物になる |
| 煽り（「限定」「今だけ」「絶対」） | 短期の売上と引き換えに、唯一の堀を失う |

## 8. 法務・規約で先に確認すべきこと

**専門家に確認すること。ここは素人判断で進めない。**

- 有料で予想を提供する場合の **特定商取引法** に基づく表記（事業者名・所在地・連絡先・返品条件など）
- 「当たる」「儲かる」等の表現に対する **景品表示法**（優良誤認）
- 競馬関連の広告・アフィリエイトの規約（未成年向け表示、賭博の助長表現）
- netkeiba からデータを取得して表示することの**利用規約上の可否**
  → 現状はスクレイピングに依存している。**商売にするなら、ここは避けて通れない。**
  公式データ（keiba.go.jp / JRA-VAN）への移行、または正規のデータ契約を検討する。

**最後の項目は事業リスクとして最大級。** 収益化を本気で進める前に片付ける。

## 9. 3か月で判断する指標

| 指標 | 3か月後の目安 | これを下回ったら |
|---|---|---|
| 月間PV | 3万 | 集客の設計を作り直す（SEOかXか） |
| 検索流入の比率 | 40%以上 | レースページのSEOが機能していない |
| Xのフォロワー増 | 月+1,000 | 発信内容を変える |
| 記事あたりの滞在 | 2分以上 | 記事が読まれていない＝書き方の問題 |

**数字が出なかったときに何を変えるかを、先に決めておく。**
決めておかないと「もう少し続ける」で1年溶ける。
