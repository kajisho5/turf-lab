## 1. 何を作るか（要件定義）

### 1.1 ひとことで
JRA-VANのデータ会員が、**自分のPCで**今日の中央競馬の予想（◎○▲△☆）と、勝負レースを見られるソフト。データはお客さん自身のJRA-VAN契約から取る。当方のサーバーを通さない。

### 1.2 売り方の前提（一次情報で確認できたこと）
出典: [ソフト登録基準](https://developer.jra-van.jp/t/topic/31)、[利用規約](https://jra-van.jp/info/rule.html)

| 項目 | 内容 | 設計への反映 |
|---|---|---|
| データの使い方 | 取得した情報は、本人が個人として私的に使う以外は複製・販売・公表・第三者提供できない（第7条） | データはお客さんのPCの中だけに置く。当方のサーバーへ送らない。予想の画像や文章を外へ出す機能は入れない（v1） |
| 登録 | ソフト登録の審査に通ると、JRA-VANのソフト一覧に載せて売れる | 登録基準15項目を満たす（下表） |
| 取得方法 | JV-Linkを使う（第13条）。HTMLページからデータを取る機能は禁止（第6条） | netkeiba等にはアクセスしない。HTMLを取りに行く処理を一切入れない |
| 配布形式 | 自己解凍のexe（第12条） | インストーラーを自己解凍exeにする |
| 試用 | 30日以上の無料試用、または機能制限付き無料版（第14条） | 30日間は全機能が使える試用にする |
| 説明書・サポート | 整備すること（第10・11条） | 説明書（HTML）を同梱。問い合わせ窓口とメールを用意 |
| 価格 | 「社会通念上妥当な価格」。改定時は登録変更。終了は3か月前に告知 | 価格は未決（あなたが決める）。終了告知の仕組みを運用に入れる |
| 削除条件 | 苦情が多い・48時間連絡が取れない・利用者が少ない等で削除されることがある | 連絡先を必ず見える所に出す |

**まだ読めていない・確認できていないこと**
- 手数料・分配の有無（読んだページに記載なし。ソフト登録係に確認が必要）
- 「予想を画面に出すこと」への制約（記載なし。確認が必要）
- ソフト名に「JRA-VAN」を含められるか（記載なし）
- 64bit版のJV-Linkで売る場合の審査の扱い（[お知らせ](https://jra-van.jp/dlb/sdv/ml/20260804a.html)では32bitの公開停止予定なし）

### 1.3 機能（v1）
1. **今日のレース**: 開催場ごとに全レースの印と、勝負レースの目印
2. **レース詳細**: 出走馬ごとの印・スコア・過去5走・血統・騎手
3. **成績**: 自分のPCに貯めた予想と結果で、◎の複勝率などを表示。**回収率は「買った全レースを分母」にする**
4. **初回セットアップ**: JV-Link接続の確認、データの初回取得（進捗つき）、試用期間の表示
5. **設定**: データ更新の頻度、保存場所、ライセンスキー入力

### 1.4 やらないこと（v1）
- 予想の画像化・共有・投稿（第7条に触れるため）
- 地方競馬（JRA-VANのデータにない）
- 馬券の購入・自動投票
- サーバーとの通信（ライセンス確認を除く。ライセンス確認でもJRA-VANのデータは送らない）

### 1.5 品質の目標
- ◎の複勝率などの数字は、**実測の範囲だけ**を表示（盛らない）。今の本番の実測は中央で未確定のため、画面の数字はお客さん自身のPCに貯まった実績から計算する
- 予想の根拠を見せる（どの因子が効いたか）。「必ず当たる」の表現は使わない

## 2. 技術選定（バージョンは公式で確認）

| 候補 | 動作の軽さ | 配布サイズ | 作りやすさ | 対応OS | 将来性 | AIでの書きやすさ |
|---|---|---|---|---|---|---|
| **A. C#（.NET 10）＋WebView2** | 軽い | 小〜中 | 普通 | Windows | 高い（LTS） | 高い |
| B. Python＋GUI | 普通 | 大（Python同梱） | 楽 | Windows | 普通 | 高い |
| C. Tauri（Rust）＋Web画面 | 軽い | 小 | 難しい（32bit部品との接続） | Windows | 高い | 普通 |

**採用: A（C# .NET 10＋WebView2）**
- JV-Link（32bitの部品）をそのまま呼べる。今のPowerShell経由の回避が不要になる。
- 画面は既存のWeb技術（HTML/TypeScript）で作れて、今の予想の画面部品を流用できる。
- .NET 10は長期サポート版で2028年11月まで更新される（[Microsoft Learn](https://learn.microsoft.com/dotnet/core/releases-and-support)）。
- 作る・配る: GitHub ActionsのWindowsランナーでビルド。Macは使わない。

**バージョン（作り始める前に最新を再確認する。記憶では決めない）**
- .NET: 10（LTS）… 上記ページで確認済み
- JV-Link: 5.0.0（SDK 5.0.0）… [お知らせ](https://jra-van.jp/dlb/sdv/ml/20260804a.html)で確認済み
- WebView2・UIライブラリ: 実装開始時に公式で確認する（未確認）

**未確認で、最初に実機で試すこと**
- .NET 10の32bit（x86）アプリからJV-LinkのCOMを呼べるか。ダメなら.NET 8（LTS）に落とす。

**予想エンジンの載せ方**
- 今の予想（`core/scoring.js` とGBMモデル）はJavaScript。これをWebView2の中でそのまま動かす。再実装しない（検算の手間と事故を避けるため）。
- 入力は、取得データから作った「出走馬と過去走の構造」を直接渡す。（今の生成器はnetkeiba形式のHTMLを作っているが、製品ではHTMLを経由せず、中の構造を直接作る。HTMLを介する処理は第6条の誤解を招くので避ける。）

## 3. 画面構成

画面は4つ。左に常に縦のメニュー（今日 / 成績 / 設定）、上に状態バー。

```
┌────────────────────────────────────────────┐
│ 状態バー: データ更新 07:02 ／ 試用あと23日     │
├──────┬─────────────────────────────────────┤
│ 今日  │  [東京] [京都] [福島]                │
│ 成績  │  1R  ◎7 ○3 ▲10 …   勝負            │
│ 設定  │  2R  …                              │
└──────┴─────────────────────────────────────┘
```

1. **今日のレース**（ホーム）: 開催場タブ → レース行（発走時刻・条件・印・勝負の目印）
2. **レース詳細**: 馬ごとの行（枠・馬番・馬名・印・スコア）。選ぶと右に過去5走・血統・騎手・根拠
3. **成績**: 期間（今月・今年）の ◎複勝率、勝負レースの結果、回収率（分母は買った全レース）。サンプル数を必ず併記
4. **セットアップ/設定**: JV-Link接続の確認、データ取得の進捗、保存場所、ライセンスキー、試用期間、問い合わせ先

## 4. 部品の分け方

```
src/
  Shell/            C#（Windowsアプリ本体）
    JvLink/         JV-Link呼び出し（JVInit/JVOpen/JVGets/JVClose）
    Store/          取得データの保存と読み出し
    Builder/        レコード → 出走馬・過去走の構造に変換（今のPython生成器を移植）
    Engine/         WebView2でスコアリングを実行する橋渡し
    License/        試用期間とライセンスキー
  Ui/               TypeScript＋HTML（WebView2の中）
    pages/          Today, RaceDetail, Results, Settings
    components/     RaceRow, HorseRow, MarkBadge, PastRunStrip, StatCard
    engine/         core/scoring.js とGBMモデル（今のものをそのまま使う）
```

## 5. 状態管理
- 状態は3つだけ: **データの鮮度**（最終取得時刻・取得中/失敗）、**今日の予想**（レース→印）、**画面の選択**（開催場・レース・馬）
- 保存は**ファイル（SQLite）**。画面を閉じても残す
- 取得に失敗したら、前回の予想をそのまま出して「古い」と明示する（空白にしない）

## 6. データ構造（お客さんのPC内）

保存先: `%LOCALAPPDATA%\TurfLab\`（設定で変更可）

| ファイル | 中身 |
|---|---|
| `jv.sqlite` | 取得レコード。**種類を絞らず全部**（RA/SE/HR/UM に加え、騎手・調教師・血統・マイニング予想・票数・調教など返ってきたもの全て）をShift-JISのまま保存。取得時刻つきで追記、上書きしない。重複は内容のハッシュで除外 |
| `pred.sqlite` | 予想（レース・馬・印・スコア・取得時点）と、結果が出たあとの照合 |
| `config.json` | 設定（ライセンスキー・保存場所・更新頻度） |
| `logs/` | 実行記録（キー・個人情報は書かない） |

予想は**発走前に確定して保存し、後から書き換えない**。成績はこの保存済みの予想だけから計算する（後知恵を入れない）。

## 7. 安全・守ること
- ライセンスキーは画面にもログにも出さない（先頭4文字+伏せ字）
- JRA-VANのデータをネットワークへ送らない。ライセンス確認の通信にもデータを含めない
- 更新・自動起動は、お客さんが設定画面でオンにしたときだけ
- アンインストール時に、お客さんのデータを残すか消すか選べる。**サービス終了後は取得データを消す**というJRA-VANの方針を説明書に書く（[運営回答](https://developer.jra-van.jp/t/topic/1390)）
