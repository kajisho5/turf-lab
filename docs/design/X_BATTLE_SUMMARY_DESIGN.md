# 設計書：朝の1枚目「今日の★勝負」と、★勝負の的中速報（2026-11-13・承認待ち）

ユーザー指示：「全場予想と両立させるには？」→「おすすめよろしく」。
全場予想を1日の幹のままにして、(A) 朝の投稿の1枚目に★勝負まとめを足す、(B) ★勝負が当たったら朝の投稿への返信で知らせる。
**この文書とデザイン（x_battle_summary.svg）の確認をもらうまで、実装はしない。**

## 1. 要件

### A. 今日の★勝負（朝の投稿の1枚目）
- 朝8:30の投稿の先頭に1枚足す。2枚目以降は今までどおり場ごとのカード。投稿文も今までどおり。
- 載せるのは、その朝に★勝負と判定したレースだけ（朝に保存する記録 pub_<場> の battle と同じもの）。別の予想は作らない。
- 1レースにつき：発走時刻／場とレース番号／条件と距離／◎の馬番と馬名／○の馬番と馬名。
- 発走の早い順に、左→右、上→下。
- ★勝負が0レースの日は、この1枚を付けない（今までと同じ投稿になる）。
- ★勝負が12レースを超える日は、信頼度の高い順に12レースまで載せ、下の帯に「ほか n レース（2枚目から）」と書く。
- 中央（jra）も同じ作り。

### B. ★勝負の的中速報（朝の投稿への返信）
- 対象は★勝負のレースだけ。◎が3着以内に来たら1件、朝の投稿への返信として出す（文だけ・画像なし）。
- 文面（例・名前は架空）:
  ```
  🎯 ★勝負 的中
  潮見3R ◎7 オッターダッシュ　1着
  単勝 250円／複勝 130円
  今日の★勝負：2戦2的中
  ```
  - 2・3着のときは「2着」「3着」と書き、払戻は複勝だけ。
  - 最後の行は、その時点までに確定した★勝負の戦績（外れも分母に入る＝当たった分だけを見せない）。
  - 払戻が取れなかったときは払戻の行を出さない（作らない・推測しない）。
- 外れたレースは速報しない（夜の答え合わせで全部出る）。ただし戦績の分母には入る。
- 1レースにつき1回だけ。出し直しや訂正はしない（降着などで変わった場合は夜の答え合わせが正）。
- 朝の投稿が無い日（投稿に失敗した日・開催なし）は何も出さない。
- 止めたいときにすぐ止められるよう、設定1つ（HITS="0"）で止まるようにする。

### やらないこと
- 予想の中身・印・★勝負の判定は変えない（判定の作り直しは別の検証。docs/SCORING_AUDIT.md 2026-11-13 の案4）。
- 発走直前のオッズを使った判断は入れない（別枠・記録がたまってから）。

### 注意（正直に書いておくこと）
- 今の★勝負（◎と○の点差8以上）は、実運用（9/28〜11/12・約600レース）で複勝回収率80.1。全体の86.6より低い。
  目立たせる前に判定を作り直すほうが筋が良い。作り直しは検証が要るので、この見た目の実装とは分けて進める
  （判定を替えても、この画像と速報はそのまま使える）。
- X への投稿は従量課金。的中速報で1日あたり数件〜十数件ぶん増える（★勝負の数×的中率）。

## 2. 技術選定
既存の仕組みに足すだけで、新しい技術は入れない（既存リポの技術は変えない方針）。

| 部品 | 使うもの | 理由 |
|---|---|---|
| A の画像 | 今の tweet.html の canvas 描画（場ごとのカードと同じ書き方・同じ色） | 見た目がそろう。フォント読み込みも今のまま |
| A の投稿 | 今の kajikeiba-autopost（Cloudflare Workers） | cards の先頭に1枚足すだけ |
| B の判定と投稿 | kajikeiba-autopost に時刻（10分おき・10:00〜22:20）を足す | X の鍵がここにある |
| B の記録 | Cloudflare D1（今の kajikeiba と同じデータベース）に表を1つ | 朝の投稿のIDと、速報済みのレースを覚える。予想・結果も同じ所から読める |

バージョン：wrangler 4.155.0（リポの package-lock のまま）。新しいライブラリは足さない。

## 5. 部品の分け方
- tweet.html
  - `battleSummaryRows(groups)`：朝の全場の結果から★勝負のレースを抜き出して並べる（描画なし・試験できる形）
  - `drawBattleSummaryCanvas(rows, total, date)`：1枚を描く
  - 朝の無人運転（auto=morning）：`__autoOut.summary = {image, count}` を足す（cards は今のまま）
- autopost（Workers）
  - `posts.js`：朝の画像の先頭に summary を足す／的中速報の文を作る `hitText()`（試験つき）
  - `hits.js`：10分おきの回。朝の投稿ID・予想・朝の★勝負・結果を読み、未速報の的中を返信で出す
  - `worker.js`：朝の投稿が成功したら投稿IDを記録／時刻で朝・夜・速報を振り分け

## 6. 状態管理・データ構造
D1 に表を1つ足す（消す処理は入れない）:
```sql
CREATE TABLE IF NOT EXISTS xpost_log (
  k TEXT PRIMARY KEY,     -- 'm:20261114:nar'（朝の投稿）または 'h:202654111407'（速報したレース）
  date TEXT NOT NULL, mode TEXT NOT NULL,
  tweet_id TEXT,          -- 朝の投稿ID / 速報の投稿ID
  body TEXT,              -- 速報の文など（確認用）
  ts INTEGER NOT NULL
);
```
- 速報の前に `INSERT OR IGNORE` で 'h:<レースID>' を取り、取れた時だけ投稿する（二重投稿を防ぐ）。
- 読むもの：predictions（朝の予想）、locks の pub_<場>（朝の★勝負）、results（確定した着順と払戻）。
