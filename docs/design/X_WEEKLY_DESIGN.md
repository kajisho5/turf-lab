# 設計書：週間まとめ（毎週月曜に1枚）（2026-11-13・確認待ち）

**確認をもらうまで実装しない。** 見本：x_weekly.svg／x_weekly.png（名前と数字は全部架空）。
印と並べ方（全場予想）には一切触らない。足すのは「先週の成績の画像を1枚投稿する」だけ。

## 要件
- 毎週月曜の朝 9:10 に、前の週（月〜日）の成績を画像1枚で投稿する。文は「先週（11/16〜11/22）の成績です」。
- 中身：大きい数字3つ（◎の3着内・複の回収率・単の回収率）／区分ごと（★勝負・狙い目・そのほか）／日ごとの◎3着内（7日）／先週いちばんの的中。
- 数字は成績表・月間まとめと同じ作り方（朝に出した予想 × 公式の着順と払戻、買った全レースが分母）。悪い週もそのまま出す。
- 150レース未満の週は投稿しない（年末年始などで開催が少ない週）。開催の無い日の枠は「開催なし」。
- 区分ごとの表は、その週の9割以上のレースに朝の区分の記録がある時だけ（月間まとめと同じ決まり）。
- 月間まとめ（毎月1日 9:00）と同じ日になっても両方出す（時刻を10分ずらしてある）。

## 技術（今ある仕組みに足すだけ。新しい言語・部品は使わない）
| 部分 | 使うもの | 理由 |
|---|---|---|
| 集計 | backtest/scoreboard.py（Python 標準ライブラリ） | 月間まとめの集計がここにある。週の区切りを足すだけ |
| 画像 | tweet.html の canvas（`?auto=weekly&wk=YYYYMMDD`） | 月間まとめと同じ描き方・同じ色と書体 |
| 投稿 | kajikeiba-autopost（Cloudflare Workers） | 月間まとめと同じ流れ。時刻の指定は増やさない（10分おきの回の「月曜 9:10」で動かす） |
- パソコンにある週間画像の道具（gen_weekly_image.js）は使わない（パソコンが要るため）。

## データ
- `/odds/data/weekly.json`（毎朝の公開で作り直す）: `{from, to, races, top3, tan, fuku, tiers:[{name,n,top3,tan,fuku}], days:[{date,n,top3}], best:{date,track,no,num,name,pay,pop}, tierCover}`
- 対象は「直前に終わった月〜日」。月曜の朝の公開で日曜ぶんの結果が入ってから作られる。
  公開が遅れて日曜ぶんが入っていない時は、投稿しない（7日そろっていない週は出さない）。

## 画面（幅1240px・高さ1180px。月間まとめと同じ枠組み）
- 見出し「先週の成績」64px／右に「地方 全○レース」「期間」の札（24px）
- 説明1行（24px）／金色の線
- 大きい数字3つ（枠365×200・数字84px・下に内訳22px）
- 区分ごとの表（見出し28px・本文24px・4列・行の高さ56）
- 日ごとの◎3着内（7枠・各152×120・日付22px・数字36px・レース数22px）
- 先週いちばんの的中（1行・26px）
- 注記（22px）「回収率は買った全レースが分母。100%未満＝買えば増える予想ではありません／馬券は20歳から」
- 色：地 #121826→#0a0e16／枠 #1b1f2b・線 #555b66／文字 白・#cccccc／★勝負 #ffd43d／狙い目 #ff8d44。どれも地に対して 4.5:1 以上（月間まとめで確認済みの組み合わせ）。文字は22px以上。

## 部品
- scoreboard.py：`weekly(races)` → weekly.json。deploy.py の MAP に追加。
- tweet.html：`weeklyUsable(j)`／`drawWeeklyCanvas(j)`／入口の一覧に weekly を追加。sw.js のバージョンを上げる。
- autopost：`runWeekly()`。記録は xpost_log に `w:週の月曜の日付`（二重投稿の防止）。

## 確認のしかた
- 先週ぶん（11/9〜11/15 が終わってから。それまでは 11/2〜11/8）で画像を作って目で確認し、数字を成績表と突き合わせる。
- 150レース未満・日曜ぶんが無い・区分の記録が足りない、の3つの場合の試験を書く。
