作成 2026-11-21。本人の決定：中央は JRA-VAN データラボに切り替える。取り込みは自分の PC（案A）。

## 3. やり方の候補

| | 案1：netkeiba と同じ形のページを自分で作る | 案2：専用の形で送り、ページを書き換える | 案3：PC で予想まで全部やる |
|---|---|---|---|
| 中身 | PC が JV-Link のデータから「出馬表のページ」と「開催一覧」を netkeiba と同じ書き方で作り、サイトの中継の保存場所に入れる。ページ側は今までどおり中継に頼むだけ | PC が JSON を送り、ページに「中央は JSON から読む」道を足す | PC が採点して印まで決め、結果だけ送る |
| ページの変更 | ほぼ無し | 多い（読み取り・採点の入口） | 多い（採点の写しを PC にも持つ） |
| 印が変わらないことの確かめ | 同じレースで「本物のページ」と「作ったページ」を同じ読み取りに通して突き合わせるだけ | 突き合わせに加えて、新しい道そのものの試験が要る | 採点の二重管理が増える（今でも tweet.html と core/scoring.js の2つ） |
| 戻しやすさ | 保存場所に入れなければ今の形に戻る | 切り替えの分岐が残る | 戻しにくい |
| 弱いところ | netkeiba の書き方に合わせ続ける必要がある | 作る量が多い | PC が止まると予想も止まる |

**おすすめは案1。** 採点には一切さわらず、入口のデータだけ差し替えるので、「変更したら前後を突き合わせる」が一番やりやすい。

## 4. 全体の流れ（案1）

```
[PC・前日 12:30／18:00／21:00、当日 6:00]
  collect_daily.py  … JV-Link で直近ぶんを取る（今あるもの）
  jra_make_pages.py … 翌日（と当日）の開催について
       ・開催一覧のページ
       ・レースごとの出馬表のページ（各馬の過去5走つき）
     を netkeiba と同じ書き方で作る（新しく作る）
  jra_push.py       … 作ったページをサイトへ送る（新しく作る）

[Cloudflare]
  /odds/jvpush.php  … 合言葉を確かめて、中継の保存場所（proxy_cache）に「JRA-VAN 由来」の印つきで入れる（新しく作る）
  /odds/proxy.php   … 中央の一覧・出馬表を頼まれたら、JRA-VAN 由来のものが新しければそれを返す。無ければ今までどおり

[朝 8:30]
  今までどおり。ページは中継に頼むだけで、返ってくるのが自分で作ったページになる
```

## 5. データの形

- 送るもの：`{ date, made_at, pages: [{ url, html }] }`。url は netkeiba と同じ（`https://race.netkeiba.com/race/shutuba_past.html?race_id=…`、`…/top/race_list_sub.html?kaisai_date=…`）。
- レースの番号（race_id）：年(4)＋場(2)＋回(2)＋日(2)＋R(2)。JV-Link のレースキーから作れる（netkeiba と同じ並び）。
- 馬の番号：JV-Link の血統登録番号（10桁）。netkeiba の馬の番号と同じ（外国産など一部は netkeiba 側が英字入りで違う。その馬は馬ごとの追加の成績が引けないだけで、過去5走はページに入っている）。
- 過去5走：PC に貯めてある過去のデータ（7月までの一括ぶん＋毎日ぶん）から馬ごとに引く。9/24〜11/16 は貯まっていないので、最初に1回だけ取り直す。
- 保存場所の行に足すもの：由来（`src='jv'`）と作った時刻。古い JRA-VAN 由来のもの（開催日を過ぎたもの）は使わない。

## 6. 送る時の守り

- 合言葉（`JV_PUSH_KEY`）を PC のファイルと Cloudflare の秘密の値の両方に入れる（入れるのは本人。私は値を見ない）。
- 受ける側は、合言葉・url が上の2種類だけか・大きさの上限・開催日が今日か明日か、を確かめる。それ以外は捨てる。
- JRA-VAN の生のデータはリポ（公開）に入れない。PC とサイトの非公開の保存場所だけに置く。

## 7. 届かなかった時

- 朝までに届いていなければ、今の形（netkeiba を中継ごしに取る → だめなら 9:00・9:20・9:40 の出し直し → 9:50 以降は発走前だけ）に自動で戻る。
- 枠順なし（区分1）のデータしか無い時はページを作らない（馬番が無いと印を出せない）。
- PC が取り込みに失敗したら、記録（`_collect.log`）に残る。投稿が出なかった日の原因はそこで分かる。

## 8. 切り替える前の確かめ（これが通るまで本番に入れない）

1. **読み取りの突き合わせ**：同じレースについて、本物の netkeiba のページと作ったページを同じ読み取り（parseShutuba）に通し、馬番・枠・馬名・騎手・斤量・過去5走の各項目が一致するかを数える。まず 11/21 の 24 レース（本物のページを保存済み）。
2. **印の突き合わせ**：同じ日について、今の形で出した予想と、作ったページで出した予想を比べ、◎○▲△ が一致する割合を出す。違いが出たレースは理由を1つずつ見る。
3. 一致しない項目が残る場合は、その項目と理由を報告し、入れるかどうかを本人が決める。
