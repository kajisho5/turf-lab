**用途**: 新しい因子や買い方を思いついた時に、この順番で検証する。
過去に何度も同じ間違い方をしているので、その落とし穴を先に潰すための手順書。

最終更新: 2026-07-19

## 大原則

**盛らない、データだけ。** 理屈が正しくても実測で悪化したら入れない／戻す。
理論的に正しい修正が実測で悪化した実例がある（GBM特徴量の修正 → FACTS.md §7）。

## 0. 着手前に必ず

1. **docs/FACTS.md を見る。** 却下済みの因子を再検証しない（馬体重・レース間隔・脚質記号・展開逆転は済み）
2. **サンプルが構造的に増やせるか考える。** 年1回の重賞のような対象は、何をやっても過学習になる

## 1. ROIの分母（最重要・過去に重大バグを出した箇所）

**投資は「買った全レース」に計上する。的中したレースだけ投資を積むと回収率を偽装する。**

過去に `pb.fuku[hon]!=null || inTop3(hon)` という条件で投資計上していたため、分母が的中レースだけになり
「◎複勝127-136%で黒字」という**誤った結論**を出した。正しく集計し直すと 78-81%（100%割れ）だった。
これを前提にした提案（複勝を看板にする等）は全て無効になった。

```python
# 正しい形
if 買う条件を満たす:
    bought += 1
    inv += 点数 * 100        # ← 的中判定の前に必ず積む
    if 的中:
        ret += 払戻
roi = 100 * ret / inv
```

**新しい集計コードを書いたら、最初に確認するのは分母の取り方。**

## 2. サンプルサイズ（小サンプルの高回収は蜃気楼）

同じ失敗を2回している。

| 事例 | 小サンプルでの見え方 | 大規模で再検証 |
|---|---|---|
| 妙味フラグ（◎5-7人気×先行） | 38R で **ROI 145%** | 4,170R で **61%** |
| 高知フォメ（実力軸） | 45R で **ROI 200%** | 1,166R で **52-90%** |

**目安: 1,000R 未満の回収率は判断材料にしない。**
的中率が数%の券種（3連単）なら、的中数が100本を超えるまで信用しない。

小サンプルで良い数字が出たら、それは「大規模で検証する価値がある」というだけの意味しかない。
UIに出すなら「参考値・少額で・未来保証なし」と明記する。

## 3. 交絡の統制（見かけの相関を潰す）

単変量で差が出ても、馬の質を統制すると消えることがある。

- **レース間隔**: 生値では休み明け37.5% vs 連闘27.4%。しかし近走好走馬に限定すると完全にフラット
  （弱い馬ほど詰めて使われるという選択バイアスだった）
- **実測先行力**: 近走着順を統制**しても** +17pt 残った → だから採用した

**必ず「近走平均4着以内の好走馬に限定」など、質を揃えた層でも差が残るか確認する。**

---

## 4. 3段階の検証フロー（標準）

```
① 独立性チェック   公式大規模データで、他の因子を統制しても差が残るか
        ↓
② 簡易モデル       backtest.py の score() に組み込んで ◎複勝率が上がるか（数万R）
        ↓
③ 実モデル         h3.js で ps 注入し、アプリの実スコアリングそのままを 2.7万R で回す
```

**②で効いても③で効くとは限らない。**最終ゲートは必ず③。
③では KILL 機構で因子の ON/OFF を切り替えて A/B を取る（両腕が同条件ならデルタは清潔）。

実測先行力の実績: ① +17pt → ② 60.08→61.88% → ③ 26,731R で 61.7% vs 59.0%（+2.7pt、3年連続プラス）

## 5. 頑健性の確認

採用の前に必ず両方見る。

- **時系列分割**: 前半・後半に割って**両方でプラス**か。片方だけなら不採用
- **時代依存性**: 血統・騎手がらみなら期間を直近3-5年に絞る（FACTS.md §6）

高知ファイナル⭐フォメは 2015-17=220% / 2018-25=137% / 2026=153% と全区分100%超だったから採用した。

## 6. 再現ゲート（ハーネスを新しく作った時）

**既知の結果を再現できないハーネスの出す新しい数字は、信用してはいけない。**

2026-07-19 の実例: 高知ファイナルの3着頭数を検証するハーネスを作ったが、
既知の「ROI156% / 638R / 的中9.1%」に対して「50.6% / 771R / 5.8%」しか出なかった。
原因は「実力上位」の定義違い（アプリは**オッズと人気補正込みの blend 順**、こちらは素の近走スコア順）。
→ **スイープ結果は採用しなかった。**

新しいハーネスを書いたら、まず既知の数字を再現する。合わなければ原因を特定するまで先へ進まない。
