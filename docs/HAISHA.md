### ① 嘘検出CI
公開している実測数字の単一台帳（16件・出典/測定日つき）とHTMLを突き合わせ、
乖離があると npm run check が落ちる。検査は3段:
1. 台帳の数字がHTMLに実在するか（HTMLだけ勝手に変わっていないか）
2. 撤回済み数字（156/169/89%）が肯定文脈で再混入していないか（撤回説明の文脈だけ許可）
3. **登録漏れ検出（2026-08-03〜）**: 対象4HTMLの【表示に出る】実測数字が台帳にも
   凍結リスト（claims_legacy_allowlist.json・棚卸し済み8種）にも無ければ落とす。
   コメント内は検査しない（監査の歴史であって公開数字ではない）。title属性は対象。
   検出器自身の故障は毎回の自己診断（selftest）で検出する。
**更新手順: 測り直し → 台帳 → HTML の順**（機械で強制される）。
実績: 初回実行で「回収169%」10件を検出。登録漏れ検出の初仕事で
「鉄板 複勝86%/ROI94%（★未検証★のまま断定表示）」を捕捉→実測84.2%/90.4%に置換(v4.3.37)。

### ② プラシーボ対照
本番で公開した◎の成績を「同レースでランダムに1頭」「1番人気」と比較。
実力 = 実測 − プラシーボ。初回実測: 的中は+21〜28ptで本物、複ROIはランダム+0.1pt(地方)
＝「当てる力は本物・市場が織り込む」を公開予想そのもので確認。
1番人気ベースラインは finishers（v4.3.30以降の答え合わせ保存）があるレースのみ。

### ③ 配車係シャドー
公開予想を**事前情報だけ**（oProb / firmO / gap / 頭数 / 場）で
「読める / 半読み / 読めない」に分類し、実測着地を影ログに蓄積。
- 分類境界(初期値): oProb≥72=読める / 60-71=半読み / <60=読めない。
  firmO<40=混戦は読めない。oProb無し（◎≠LTRトップ）は firmO にフォールバック。
- 見送り理由の分類（#15）: oProb低 / データ不足 / 混戦 を記録。
- **昇格判定（機械）**: 各分類N≥150 かつ 読めるのWilson95%下限 > 読めないの上限
  → 合格なら表示（堅い/荒れ注意ラベル等）への昇格を**提案**（実施はユーザー判断）。
  それまで本番には出さない。境界の引き直しは jsonl の gap/oProb/firmO 列で再分析できる。

#### 蓄積の見通し（2026-08-04時点・212R / 7-31〜8-3）
| 分類 | N | ◎複勝率(Wilson95%) | 1日あたり | 150Rまで |
|---|---|---|---|---|
| 読める | 24 | 75.0%（55.1-88.0） | 6.0R | **約21日**（8月下旬） |
| 半読み | 97 | 55.7%（45.8-65.2） | 24.2R | 約3日 |
| 読めない | 91 | 62.6%（52.4-71.9） | 22.8R | 約3日 |

- **ボトルネックは「読める」**（oProb≥72が厳しく1日6Rしか出ない）。判定は8月下旬の見込み。
- 現時点で 読める > 読めない の向きは出ているが、**半読みが最下位という逆転**がある。
  分類設計の見直し材料になりうるが、★N不足の段階では触らない★（多重比較で偽陽性を作る）。
  引き直しは四半期単位という取り決めを守り、判定時にまとめて見る。
- ★結果保存が無い日は蓄積も止まる★ 2026-08-04に結果の自動保存(push_results.py)を
  日次へ入れるまで、答え合わせをしなかった日はデータの穴になっていた（166R→212Rに回復）。

## 運用
- 蓄積は全自動（daily.py 4:30）。人手は不要。
- 判定が「合格」を出したら SCORING_AUDIT に記録し、ユーザーに表示昇格を提案する。
- 新しい公開数字を作ったら **必ず claims_registry.json に登録**。2026-08-03から
  **登録漏れもCIが検出する**: 対象4HTMLに現れる実測数字（複勝率/的中率/回収/ROI系×NN%）が
  台帳にも `claims_legacy_allowlist.json`（2026-08-03時点の既存108種を凍結した基準線）にも
  無ければ check_claims が落ちる。「測る→台帳→HTML」の順が機械で強制される。
  レガシー凍結リストは棚卸しで徐々に縮める（数字をHTMLから消したらリストからも消してよい）。

## 明示的にやらないこと
- narM/jraM（オッズ込みモデル）を事前予想に混ぜること（建前が壊れる）
- N不足のまま分類を表示に出すこと（高知⭐156%の再演になる）
- 影ログの結果を見て境界を毎週いじること（多重比較で偽陽性を作る。引き直しは四半期単位）
